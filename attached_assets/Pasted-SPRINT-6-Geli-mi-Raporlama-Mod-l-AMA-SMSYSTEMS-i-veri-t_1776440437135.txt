SPRINT 6 — Gelişmiş Raporlama Modülü

AMAÇ:
SMSYSTEMS’i “veri tutan sistem” seviyesinden çıkarıp “karar verdiren sistem” seviyesine taşımak. Bu sprint sonunda kullanıcı sadece satış ve stok görmekle kalmayacak; hangi ürün iyi gidiyor, hangi kategori kazandırıyor, hangi personel performanslı, nerede kâr düşüyor, iade oranı nerede yükselmiş gibi sorulara net cevap alabilecek.

Bu sprint sonunda kullanıcı:

* tarih aralıklı gelişmiş raporlar alabilecek
* ürün / kategori / marka bazlı satış performansını görebilecek
* personel bazlı satış performansını görebilecek
* iade oranlarını inceleyebilecek
* kârlılık ve düşük marjlı ürünleri görebilecek
* raporları Excel / CSV / PDF olarak dışa aktarabilecek

==================================================

BACKEND API TASARIMI
====================

1. Satış Trendi

GET /api/reports/sales-trend?from=YYYY-MM-DD&to=YYYY-MM-DD&groupBy=day|week|month

Response:
{

{

salesCount,
revenue,
returnedCount,
returnedAmount,
netRevenue
}
],
totals: {
salesCount,
revenue,
returnedCount,
returnedAmount,
netRevenue
}
}

6. Kârlılık Raporu

GET /api/reports/profitability?from=YYYY-MM-DD&to=YYYY-MM-DD&groupBy=product|category|brand

Mantık:

Not:
İlk sürümde estimatedCost için ürünün satış anındaki cost snapshot’ı yoksa,
mevcut/son maliyet veya sale item’a eklenen maliyet snapshot alanı kullanılmalı.

* netRevenue = revenue - returnedAmount

Önerilen returnRate:
returnCount / totalSoldCount veya returnedQuantity / soldQuantity
Birini seçip her yerde aynı uygula.

==================================================
KÂRLILIK HESABI DETAYI
======================

İlk sürüm için öneri:

sale item oluşurken:

* unit_cost_snapshot
* total_cost_snapshot

sakla.

Böylece sonradan ürün maliyeti değişse bile geçmiş rapor bozulmaz.

Rapor formülleri:

revenue = sum(sale_items.total_price)
estimatedCost = sum(sale_items.total_cost_snapshot)
estimatedProfit = revenue - estimatedCost
marginPct = estimatedProfit / revenue * 100

Eğer snapshot henüz yoksa:

* geçici fallback ile current purchase_price kullanılabilir
* ama bu dokümana “yaklaşık kârlılık” diye yazılmalı

PERFORMANS / INDEX / TEKNİK NOTLAR
==================================

Önemli:
Bu sprint ağır sorgu sprintidir.
Kodu yazıp bırakmayın; sorguları optimize edin.

Önerilen indexler:

* sales(company_id, created_at)
* sales(company_id, user_id, created_at)
* sales(company_id, returned, created_at)
* sale_items(company_id, product_id)
* products(company_id, category)
* products(company_id, brand)

Teknik öneriler:

* büyük raporlarda aggregation SQL seviyesinde yapılsın
* N+1 sorgu yapılmasın
* count + data query ayrımı düzgün olsun
* gerekirse materialized summary sonraki sprintte düşünülür
* export büyükse ileride async job’a taşınabilir
