SPRINT 4 — Cari / Müşteri Takibi Modülü

AMAÇ:
SMSYSTEMS’i sadece stok programı olmaktan çıkarıp işletmenin günlük tahsilat, borç/alacak ve müşteri ilişkilerini yönettiği sisteme çevirmek.

Bu sprint sonunda kullanıcı:

* müşteri ekleyebilecek
* müşteriye satış bağlayabilecek
* müşterinin borcunu görebilecek
* tahsilat alabilecek
* cari hareketlerini inceleyebilecek
* müşteri bazlı satış geçmişi görebilecek

==================================================
GENEL TESLİM KURALLARI
======================

* Multi-tenant izolasyonu zorunlu
* company_id scope her sorguda uygulanacak
* auth + role kontrolü olacak
* standart error formatı kullanılacak
* audit log kritik işlemlerde çalışacak
* integration test yazılacak

* docs güncellenecek

2. customer_transactions

id

(source: sale | payment | adjustment | refund)

(debit | credit)

amount
reference_type nullable
reference_id nullable
description nullable
created_by
created_at

Mantık:
debit  = müşterinin borcu arttı
credit = müşterinin borcu azaldı

---

3. sales tablosuna ek alan

customer_id nullable

Bir satış müşteriye bağlanabilir.

==================================================
BAKİYE HESAP MANTIĞI
====================

current_balance = toplam debit - toplam credit

Örnek:
10.000 satış = debit
4.000 tahsilat = credit

Bakiye = 6.000

Not:
İlk versiyonda customers.current_balance tutulabilir.
Her işlem sonrası transaction ile güncellensin.

==================================================
BACKEND API
===========

1. Müşteri CRUD

GET /api/customers

* pagination
* search
* active filter

GET /api/customers/:id

POST /api/customers

PUT /api/customers/:id

DELETE /api/customers/:id
(soft delete => is_active=false)

PATCH /api/customers/:id/restore

---

2. Cari İşlemler

GET /api/customers/:id/transactions

POST /api/customers/:id/payment

Body:
{
amount,
paymentMethod,
note
}

Bu işlem:

* customer_transactions içine credit kayıt açar
* bakiye düşer
* audit log atar

POST /api/customers/:id/adjustment

Body:
{
amount,
direction,
note
}

Manuel bakiye düzeltme

---

3. Satış Bağlama

POST /api/sales

Mevcut satış endpoint’ine ekle:

customerId optional

Satış müşteriye bağlıysa:

* sale oluşur
* customer_transactions içine debit oluşur
* bakiye artar

---

4. Rapor Endpointleri

GET /api/customers/top-debtors
GET /api/customers/:id/statement
GET /api/customers/:id/sales
