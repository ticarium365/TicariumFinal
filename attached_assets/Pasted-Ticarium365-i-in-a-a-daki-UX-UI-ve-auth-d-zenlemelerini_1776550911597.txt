Kullanıcı ilk ekranda “kurumsal ve temiz” his alsın.

==================================================
5. ŞİFREMİ UNUTTUM / TELEFONLA ŞİFRE SIFIRLAMA
==============================================

Yeni akış:

Adım 1:

* kullanıcı telefon numarasını girer

Adım 2:

* sistem SMS doğrulama kodu yollar
  veya
* geçici şifre reset linki / kodu üretir

Adım 3:

* yeni şifre belirlenir

Gerekli backend değişiklikleri:

* users tablosunda phone alanı zorunlu/opsiyonel düzenlensin
* phone doğrulama mantığı eklensin
* password reset tokens tablosu veya sms_verifications tablosu eklensin
* rate limit olsun
* brute force koruması olsun
* audit log yazılsın

Gerekli endpointler:

* POST /api/auth/forgot-password
* POST /api/auth/verify-reset-code
* POST /api/auth/reset-password

Opsiyonel:

* SMS provider yoksa önce mock + admin test mod
* sonra Netgsm / ilgili SMS sağlayıcı ile gerçek gönderim

==================================================
6. "VERİ İHLALİ" MESAJI TEMİZLENSİN
===================================

Sorun:
Şifre girince kullanıcıyı korkutan veya yanlış çağrışım yapan “veri ihlali” mesajı çıkıyor.

İstenilen:

* bu hata kesin incelensin
* metin yanlışsa düzeltilsin
* gerçekten HIBP veya benzeri breach check yapılıyorsa kullanıcı diline uygun çevrilsin
* girişte korkutucu, gereksiz alarm veren metin kalmasın

Yeni yaklaşım:

* gerçek güvenlik riski yoksa bu metin hiç görünmesin
* gerekiyorsa arka planda loglansın
* kullanıcıya sade mesaj verilsin:

  * “Şifre doğrulanamadı”
  * “Giriş bilgileri kontrol edilemedi”
  * “Lütfen tekrar deneyin”

Ama “veri ihlali” gibi direkt panik üreten metin login ekranında gösterilmesin.

Ayrıca kontrol et:

* bu mesaj frontend hardcoded mı
* auth endpoint’ten mi geliyor
* third-party password breach uyarısı mı
* session / csrf / cookie probleminden mi yanlış yorumlanıyor
